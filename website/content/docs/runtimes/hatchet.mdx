# Hatchet Runtime

[Hatchet](https://hatchet.run) is a serverless durable-function engine. The `hatchet/` package wraps it as a `graft.Runner`, so any agent you build with Graft can execute under Hatchet with retries, fan-out/fan-in DAGs, and per-key rate limits.

## Installation

```bash
go get github.com/delavalom/graft/hatchet
```

Graft does **not** import the Hatchet SDK. Instead, `hatchet.HatchetClient` is a small Go interface mirroring the SDK surface — you inject your own `*hatchet.Client` at runtime.

## Basic Usage

```go
import (
    "github.com/delavalom/graft"
    "github.com/delavalom/graft/hatchet"
    "github.com/delavalom/graft/provider/openai"
)

model := openai.New(
    openai.WithAPIKey(os.Getenv("OPENROUTER_API_KEY")),
    openai.WithBaseURL("https://openrouter.ai/api/v1"),
    openai.WithModel("anthropic/claude-sonnet-4.6"),
)
_ = model // the model is used by the Hatchet worker, not the client

var hatchetClient hatchet.HatchetClient // your real *hatchet.Client

runner := hatchet.NewHatchetRunner(hatchetClient,
    hatchet.WithNamespace("production"),
    hatchet.WithConcurrency(5),
    hatchet.WithRateLimit("openai", 100),
)

agent := graft.NewAgent("durable-assistant",
    graft.WithInstructions("You are a helpful assistant running as a durable function."),
)

result, err := runner.Run(context.Background(), agent, []graft.Message{
    {Role: graft.RoleUser, Content: "What are the advantages of durable functions?"},
})
```

See [`examples/hatchet/main.go`](https://github.com/delavalom/graft/blob/main/examples/hatchet/main.go) for a complete, runnable example.

## Runner Options

```go
hatchet.NewHatchetRunner(client,
    hatchet.WithNamespace("production"),     // Hatchet namespace
    hatchet.WithConcurrency(5),              // max parallel workflow runs
    hatchet.WithRateLimit("openai", 100),    // 100/sec for the "openai" key
)
```

| Option | Purpose |
|--------|---------|
| `WithNamespace(string)` | Scope workflows to a Hatchet namespace |
| `WithConcurrency(int)` | Cap parallel workflow executions |
| `WithRateLimit(key, limit)` | Per-key rate limit (e.g. per provider) |

## Tools as Hatchet Tasks

The runtime can treat an existing Hatchet task as a Graft tool via `TaskAsTool`:

```go
tool := hatchet.TaskAsTool(
    "enrich-user",
    "Fetch the user's profile and recent activity.",
    schema,
    hatchetClient,
    hatchet.WithTaskRetry(&hatchet.RetryConfig{ /* ... */ }),
)

agent := graft.NewAgent("assistant",
    graft.WithTools(tool),
)
```

Each tool invocation becomes a Hatchet task execution with its own retry policy, so transient failures never bubble up to the agent loop.

## DAG Workflows

For more complex orchestration, Graft ships a prebuilt agent-loop DAG (`generate → execute-tools → check-done`) you can extend:

```go
dag := hatchet.NewAgentDAG("my-agent")
dag.AddStep(hatchet.DAGStep{
    Name:      "post-process",
    TaskName:  "summarize-output",
    DependsOn: []string{"check-done"},
})
```

Register the DAG with your Hatchet worker — Graft only defines the shape, execution is Hatchet-native.

## When to Choose Hatchet

- You want DAG-level parallelism (fan-out across tools, fan-in before the next LLM call).
- You need per-key rate limiting tied to specific providers or tools.
- You prefer a Postgres-backed engine over Temporal's event history model.
